# The gitignore TOML format

## Overview

`how_to_do_gitignore.toml` holds the rules used to build `.gitignore` files,
grouped into categories. The rules are merged with the user's own file during
installation and upgrades.

## File structure

### Basic shape

```toml
# A rule category
CategoryName = { patterns = [
  "pattern1",           # comment
  "pattern2",           # another comment
  "pattern3"            # last pattern
]}
```

### Example categories

```toml
####################################################################
# [OperatingSystem] - OS clutter (macOS, Windows, Linux)
OperatingSystem = { patterns = [
  ".DS_Store",           # macOS Desktop metadata
  "Thumbs.db",           # Windows Explorer thumbnail cache
  "ehthumbs.db",
  "Icon?",
  ".Spotlight-V100",
  ".Trashes",
  "*.swp", "*.swo", "*~" # Vim/shell backup files
]}

####################################################################
# [IDE] - files generated by editors and IDEs
IDE = { patterns = [
  ".idea/", "*.iml", "*.iws", "*.ipr",           # JetBrains IDEA / PyCharm / etc.
  ".vscode/", "*.code-workspace",                # Visual Studio Code
  ".cursor/", "*.cursor-workspace",              # Cursor IDE
  "*.sln", "*.suo", "*.user", "*.ncb", "*.sdf",  # Visual Studio
  ".metadata/", ".classpath", ".project",        # Eclipse
  "*.launch",                                    # Eclipse run configs
  "*.sublime-project", "*.sublime-workspace",    # Sublime Text
  ".atom/",                                      # Atom
  ".emacs.d/", "*.elc", "*.eln",                 # Emacs
  ".vim/", "*.viminfo",                          # Vim
  "#*#",                                         # Generic lock/temp
  "*.tmproj"                                     # TextMate
]}
```

## Naming rules

### Categories
- Use PascalCase for category names
- Names should be descriptive
- Avoid special characters other than the underscore

### Patterns
- Use standard gitignore patterns
- Wildcards are supported: `*`, `?`, `[abc]`
- Negations are supported: `!pattern`
- Directories are supported: `dir/`

## The merge process

### Precedence
1. **User rules** take precedence over the distributed ones
2. **New categories** from the user file are added
3. **Duplicates** are removed automatically
4. **Comments** from the user file are preserved

### Merge algorithm
```python
# Pseudocode for the merge
for category in distributor_categories:
    merged_data[category] = distributor_patterns[category]

for category in user_categories:
    if category in merged_data:
        # Merge the rules and deduplicate
        merged_patterns = deduplicate(user_patterns + distributor_patterns)
        merged_data[category] = merged_patterns
    else:
        # Add the new category
        merged_data[category] = user_patterns
```

## Examples of user rules

### Adding more IDEs
```toml
IDE = { patterns = [
  ".vscode/",            # Visual Studio Code
  ".sublime-project",    # Sublime Text (custom)
  ".atom/",              # Atom (custom)
  ".brackets.json",      # Brackets (custom)
  "*.sublime-workspace"  # Sublime workspace (custom)
]}
```

### Creating a new category
```toml
CustomProject = { patterns = [
  "config/local.json",   # local settings
  "logs/",               # application logs
  "temp/",               # temporary files
  "cache/",              # application cache
  "uploads/",            # uploaded files
  "backups/"             # backups
]}
```

### Extending an existing category
```toml
Python = { patterns = [
  "venv/",               # virtual environments
  "pip-wheel-metadata/", # pip metadata (custom)
  ".tox/",               # tox (custom)
  ".pytest_cache/",      # pytest cache (custom)
  ".coverage",           # coverage reports (custom)
  "htmlcov/"             # coverage HTML (custom)
]}
```

## Error handling

### Malformed TOML
- If the user file fails to parse, only the distributed one is used
- A warning is logged about skipping the user file
- Installation continues

### Missing files
- If the user file is missing, only the distributed one is used
- If the distributed file is missing, an error is raised

### Structure validation
- Data types are checked
- The category structure is validated
- Required fields are checked

## Best practices

### Organising rules
- Group related patterns into a single category
- Use descriptive category names
- Comment complex patterns

### Compatibility
- Use standard gitignore patterns
- Test patterns against real projects
- Avoid overly specific patterns

### Updates
- Refresh the distributed file regularly
- Check that user rules stay compatible
- Back up before upgrading

## Debugging

### Logging
- Every merge operation is logged
- Parse errors are written to the log
- Validation results are printed

### Diagnostics
```bash
# Check the file structure
python3 -c "import tomllib; tomllib.load(open('how_to_do_gitignore.toml', 'rb'))"

# Check the merge
python3 -c "from how_to_do import merge_gitignore_rules; print(merge_gitignore_rules())"
```

## Migration

### From the old format
- Old files are converted automatically
- Backward compatibility is preserved
- Warnings are logged about the deprecated format

### To the new format
- New features require the updated format
- Upgrading is recommended where possible
- A migration tool is provided
